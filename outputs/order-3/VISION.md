# ORDER//3 — 面白さの仮説と開発方針

## このゲームの核

一言で表すと、ORDER//3は「仲間を選ぶことがデッキ構築になり、敵の予告に対して3手の連携を組み立てるゲーム」である。

面白さの中心はカード単体の強さではない。盤面上の位置、誰がそのカードを使えるか、前後の命令で何が変わるかを同時に考え、複数人の行動がひとつの作戦としてつながることにある。

### 1. 編成がそのままデッキになる

仲間1人は、盤面上の駒であると同時に固有カードの束でもある。仲間を入れ替えると、射程、守備範囲、移動能力、手札の性質がまとめて変化する。この「ユニットとカードの不可分性」が最大の独自性になる。

### 2. 敵の予告に対して3手で答える

敵の行動は読めるが、すべてには対処できない。攻撃、回避、妨害、準備のどれを優先するかを選び、限られた3命令で被害と好機を交換する。正解探しではなく「何を受け入れるか」を決めるゲームにする。

### 3. 位置とカードが互いを書き換える

移動によって次のカードの射程が変わり、攻撃によって別のユニットの連携条件が整う。カードを順番に置くことが、小さなプログラムを組む感覚になる。計画後の盤面を明瞭にプレビューし、考える難しさと操作の難しさを分離する。

### 4. 仲間を失うことが戦術と物語を同時に変える

倒れた仲間のカードが遺志へ変わる仕組みは、FE的な喪失とデッキ変化を一つにできる。ただし即死や長期的な取り返しのつかなさは後から検討し、最初は一戦内の負傷として扱う。

## 参考作品から借りるもの

### FEから：盤面上の役割と部隊への愛着

- 上下左右の距離、攻撃範囲、地形、進路封鎖を明瞭にする。
- 前衛、射手、術師など、誰をどこへ置くかで役割が変わるようにする。
- 敵全体の危険範囲を一目で確認できるようにする。
- 撃破だけでなく、防衛、離脱、護衛、拠点制圧を導入する。
- 支援関係は数値ボーナスだけでなく、2人で使える連携カードとして表現する。
- 大人数化は避け、3人だから全員の行動を把握できる密度を守る。

### MTGから：色の個性、応酬、構築の発見

- キャラクターごとに「できること／苦手なこと」を厳格に分ける。
- 単体で強いカードより、別のカードや盤面条件で化けるカードを増やす。
- 同じ効果の数値違いではなく、攻め方そのものが変わる編成を用意する。
- 防御や妨害は、敵の強い行動を完全に消すだけでなく、タイミングや対象をずらす方向を重視する。
- すべてのカードを移動に変換できる規則は手札事故を防ぐ一方、固有技より移動が常に正解にならないよう、移動の機会費用を観察する。

### Slay the Spireから：予告、敵知識、ランの意思決定

- 敵の意図を表示し、プレイヤーが損失を計算できるようにする。
- 敵はランダムな技表ではなく、学習できる短いパターンと条件分岐を持つ。
- 通常敵は一つの判断を教え、エリートは複数の判断を重ね、ボスは構築全体を試す。
- カード報酬にはスキップを用意し、増やすだけでなく削ることを価値にする。
- 分岐マップでは、戦闘、回復、加入、強化、危険な報酬を比較させる。
- 高難度化は敵HPの増加だけでなく、予告パターンや編成制約を変える。

## 現在の危険

### 完全情報の一問一答になる

敵の予告に対する専用回答が毎回一つだけなら、手札に回答があるかどうかの確認になる。各脅威へ最低三種類の対処法を持たせ、どれも別の代償を伴うようにする。

### 共有デッキが仲間を動かせないストレスになる

手札にその仲間のカードがなければ、盤面にいるのに何もできない。万能移動だけで解決せず、各ユニットに毎ターン使える弱い基本行動を与える案を比較検証する。

### 3命令が最適コンボの再生だけになる

同じ三枚が常に最大火力なら、盤面と敵予告が意味を失う。敵の反応、地形、目標、速度差によって並べ方の価値が変わる必要がある。

### 要素を足しすぎて読めなくなる

カードゲーム、SRPG、ローグライクを同時に増築すると認知負荷が急増する。一回の更新では一つの仮説だけを変更し、UIの明瞭さを先に守る。

## 面白くするための優先順位

### P0：戦闘の読みやすさ

1. 全行動を一本のタイムラインで表示する。
2. 移動を含む全命令の最終位置をプレビューする。
3. 予測ダメージ、撃破、装甲消費、状態変化を実行前に表示する。
4. FE式の危険範囲表示を追加する。

### P1：選択の深さ

1. 各敵に三つ以上の対処法を用意する。
2. 基本行動と手札制の関係を比較する。
3. 連携条件を持つカードを各キャラクターに二枚ずつ追加する。
4. 撃破以外の勝利条件を持つ第二戦闘を追加する。

### P2：ローグライクのラン構造

1. 戦闘後に「カード追加／既存カード強化／仲間候補」の三択を置く。
2. 3戦＋エリート＋ボスの短い分岐マップを作る。
3. 2人の追加キャラクターを作り、3人を選ぶ編成判断を成立させる。
4. 一回のランを30〜45分に収める。

## OODAで使う評価基準

各更新は、以下のどれを改善するのか明記する。

- Readability：実行前に結果を説明できるか。
- Agency：悪い結果を自分の判断の結果だと感じられるか。
- Variety：同じ敵に異なる有効策があるか。
- Identity：キャラクターと編成でプレイ感が変わるか。
- Tempo：一ターンの計画と実行が長すぎないか。
- Recovery：失敗後にも意味のある選択が残るか。

一周のOODAでは一つの仮説だけを実装する。観察なしの大量追加、数値だけの調整、テストを伴わない変更は行わない。

## 最初の開発仮説

次に検証する価値が最も高いのは「実行前の結果予測があれば、3手コンボを考える楽しさが増え、試行錯誤のストレスが減る」である。

まず計画中に、各行動後の予定HP、装甲、状態異常、撃破予定を段階表示する。これが機能してから、第二戦闘やラン構造へ進む。
